# 🕰️ Laima

[🇺🇸 English](../../README.md) · [🇧🇷 Português](../pt/README.md) · **🇷🇺 Русский** · [🇮🇳 हिन्दी](../hi/README.md) · [🇨🇳 中文](../zh/README.md) · [🇪🇸 Español](../es/README.md)

Библиотека TypeScript/JavaScript для преобразования, сравнения, изменения и форматирования дат без зависимостей времени выполнения. Необязательная CLI входит в тот же npm-пакет.

> Описанные дополнения находятся в разработке (см. [CHANGELOG](../../CHANGELOG.md)) и появятся в npm после следующей публикации. Версия пакета пока не изменена.

## Установка и использование

```sh
npm install laima
```

```ts
import Laima from 'laima';

const laima = new Laima();
const date = laima.parseISODate('2024-02-29');
console.log(laima.formatDate(date, 'DD/MM/YYYY')); // 29/02/2024
console.log(laima.addDays(date, 1)); // новый Date; исходная date не изменяется
```

```js
const Laima = require('laima').default;
const laima = new Laima();
console.log(laima.format());
```

[Полная справка API на английском](../en/API.md) · [Справка на португальском](../pt/API.md)

## Инструменты даты и времени

Типизированный API включает календарную арифметику и расчёт прошедшего времени, месяцы и годы с ограничением до последнего допустимого дня, границы периодов, разницы со знаком, включительные интервалы, недели ISO, метаданные, возраст, рабочие дни с понедельника по пятницу, секунды Unix, компоненты длительности и форматирование в часовых поясах IANA. Новые методы проверяют входные данные и не изменяют исходные даты. См. [расширенный API и типы на английском](../en/API.md#extended-api).

```ts
const date = new Date('2024-01-31T12:00:00Z');
laima.add(date, 1, 'month', { utc: true }); // 2024-02-29T12:00:00.000Z
laima.getISOWeek(date, { utc: true });
laima.getDurationParts(-1500);
```

## Использование в терминале (необязательно)

Установите Node.js и npm. CI проверяет Node.js 22 и 24 на Linux, macOS и Windows.

```sh
npx laima --help
npx laima format 2024-02-29T12:00:00Z "DD/MM/YYYY HH:mm" --utc
npx laima add-days 2024-02-28 1
npx laima diff 2024-01-01 2024-01-10
npx laima date 0
```

Чтобы запускать `laima` напрямую:

```sh
npm install --global laima
laima --help
```

Даты без времени используют местную полночь. Временные метки должны содержать `Z` или смещение (`±HH:mm`). Форматирование использует местное время, если не указан `--utc`. Команды `date` и `add-days` выводят ISO-метки времени в UTC. Ошибки направляются в stderr с кодом выхода 1; успешные результаты — в stdout с кодом 0. См. [справку CLI на английском](../en/API.md#cli).

## Совместимость

Существующие импорты и методы остаются доступными. Разница в днях — абсолютное число 24-часовых периодов с округлением; она не показывает, истёк ли срок. Календарные операции используют местное время и могут пересекать переходы на летнее время.

- `format(pattern?)` сохраняет прежний алгоритм. Используйте `formatDate(date, pattern?, options?)` для повторяющихся токенов, литералов в квадратных скобках и UTC.
- `parseDateFromDB` по-прежнему допускает нормализацию `DD-MM-YYYY`, а `formatDateForDB` возвращает `YYYY-MM-DD`. Для строгого чтения последнего формата используйте `parseISODate`.
- Сохраняется стандартное переполнение месяцев: 31 января плюс один месяц может дать дату в марте. `addMonths` сбрасывает время до полуночи; `subMonths` сохраняет время суток.
- Отладочный вывод удалён. Прежняя обработка недопустимых дат сохраняется; новые строгие методы выбрасывают `RangeError`.

## Структура проекта

```text
src/
  laima.ts           # фасад публичного API
  types.ts           # общие типы
  core/              # операции с датами по обязанностям
  cli.ts             # точка входа исполняемого файла
  cli/               # команды, разбор аргументов и справка
tests/
  unit/              # поведение модулей и CLI
  compatibility/     # прежние контракты и особенности
  integration/       # установка и использование npm-пакета
config/              # Jest, commitlint и TypeScript тестов
scripts/             # очистка сборки и хуки разработки
docs/                # документация по языкам
dist/                # результат сборки
```

См. [описание архитектуры на английском](../en/ARCHITECTURE.md), чтобы узнать обязанности модулей и расположение изменений.

## Разработка и участие

Используйте Node.js 22 или 24 и npm:

```sh
npm ci
npm run check
```

`check` выполняет lint, Prettier, проверку типов, тесты покрытия и проверку пакета у потребителя. В [CONTRIBUTING](../../CONTRIBUTING.md) описаны хуки, Conventional Commits, тесты часовых поясов, переводы и выпуски; руководство доступно на английском и португальском.

[Конфигурация CodeRabbit](../../.coderabbit.yaml) требует установки и авторизации приложения сопровождающим в репозитории GitHub. Один файл конфигурации не активирует сервис; см. [официальную документацию](https://docs.coderabbit.ai/reference/configuration).
